**你若是一个刚 clone 下这个仓库的 AI，只做三件事：**

1. 读 **[`WORKBUDDY.md`](WORKBUDDY.md)**（协作流程与敢不敢直推的边界）和 **[`AGENTS.md`](AGENTS.md)**（项目宪法）。这两份读完再动手，冲突时 `WORKBUDDY.md` 优先。

**红线文件**（必须开 `wb-*` 分支发 PR，不许直推 main）：`src/scripts/01b_engine_data.js`、

## 它是什么

计时只是规则，养成才是玩法。完成番茄获得的🍅折算为树的成长与金币，驱动一整套游戏系统：

- **番茄树**：9 阶段成长、多树种图鉴、浇水/投喂/装饰/场景/光环/天气
- **经济**：金币商店、动态定价、道具库存、断签保护
- **玩法**：抽卡扭蛋、段位排行（11 档+星级）、周挑战、赌注、组队专注、传记系统
- **沉浸模式**：角色卡+章节式冒险剧本，专注过程推进剧情

也有不游戏化的硬功能：待办（含快捷语法与子任务）、习惯打卡、统计（热力图/周报/趋势）、日记、倒数日、数据导入导出。

## 架构速览：三层

**L1 计时内核**——番茄钟本体与数据底座
`00_pure_core`（纯函数）· `01a` 引导 · `01b` 数据层（IndexedDB 主存 + localStorage 镜像 + 版本迁移链）· `01c` 计时引擎 · `01d` 结算域 · `01e` 主 UI · `01g` 启动

**L2 游戏系统**——养成与玩法（各自成域，可整段回退）
`01d2` 段位/人机榜 · `01d3` 树商店/金币经济 · `01d4` 组队 · `01d5` 统计缓存 · `01f` 沉浸冒险 · `02/03/05` 增强模块 · `0E` 主题引擎（6 主题 × 明暗双模式，CSS 变量为唯一真相源）

**L3 工程链**——把 33 个源文件合成单文件产物，并守住质量
`tools/build.py` 九槽声明式合成 · `tools/verify.py` 十段验证链 · `tools/w6_*` 架构门禁 · `tools/tests/` 单测 + E2E

```
src/scripts/*.js ──build.py──> index.html（单文件产物，2.1 MB）
                     │
verify.py 十段门禁：lint → build → check → layer → toc → size → unit → catch → e2e → smoke
```

## 工程纪律（这个仓库认真在哪）

- **十段验证链**：任一改动可一键自证——77 条浏览器端到端动线 + 99 项冒烟断言 + 27 条纯函数单测，全绿才算完。
- **架构规约有牙齿**：五层依赖方向硬门禁（`w6_layer.py`）、文件头函数索引一致性（`w6_toc.py`）、单文件 6000 行红线（`w6_size.py`）、innerHTML 注入签名级基线扫描、空 catch 棘轮（只减不增）。
- **安全防线**：CSP meta（禁外发/禁外脚本）、备份导入深度净化（防原型污染）、用户输入全链路转义（扫描器守门）。
- **契约式维护**：每个文件头有「耦合契约」注释（对外白名单 + 红线），增强模块只许包装不许改写，`AGENTS.md` 是维护宪章。

## 以后想请 AI 改东西（完整闭环，照着做就行）

**① 怎么把项目交给 AI —— 分两种情况：**

| 情况 | 你做什么 |
|---|---|
| AI 能直接打开这个文件夹（像现在这样） | **什么都不用传**。直接说："改我项目里的番茄专注，先读 AGENTS.md，我要……" |
| 换了新 AI / 新对话，它看不到文件夹 | 把**整个项目 zip**（番茄专注-完整项目.zip）解压后给它 **`src/` + `AGENTS.md` + `tools/`**（不用给 `docs/` 和两个合成器网页） |

> 记法：AI 干活要三样东西 —— 源码（src/）、规矩（AGENTS.md）、工具（tools/）。别的都可省。

**② 它改完之后会还你什么：**

1. **一份大白话《改动说明》**（改了什么 / 加没加功能 / 你打开能感觉到啥）——这是它必须交的，你不用自己看代码；
2. **完整的最新项目包**（zip 或整包）——你解压后**整个替换**旧文件夹即可，不用关心它改了哪几个文件，反正全给你了。

> 一句话：**你发整包、它还整包 + 人话说明，中间你永远不用猜。**

剩下的流程（在哪改、怎么测、怎么保证不改坏）都写死在 `AGENTS.md` 里，AI 会自己遵守。

## 🔒 模块耦合契约（给接手维护者 / AI 的规矩，改代码前必读）

> 背景：项目目前是**单文件多模块**结构（33 个 src 文件、约 1100+ 个全局函数、跨文件调用 2400+ 次），
> 耦合度**偏高**。以下契约是为了"降耦但不牵一发动全身、不影响合成"，请遵守。

1. **先看文件头的「E3 耦合契约」注释**：01a–01g、02/03/05/06/07/08 每个文件头都写明了
   「对外白名单 + 红线」，改哪个文件先读哪个文件头。
2. **禁止复制第二份同名实现**（历史事故：updateTitle×2、年度热力图×2）。
   加功能前先 grep，发现已存在同职责函数就包装或复用，别再造一个。
3. **新增 appData 字段**必须同步补默认值；设备 UI 态（折叠/引导/歌单/剧情/角标/公告等）进 `appData.uiPrefs.*`，不新增 localStorage 键（落地见 `docs/current/AI_SCAFFOLD.md`）。
4. **新纯函数**进 `00_pure_core.js`；**新 UI 组件**走 `registerComponent()`（槽 8）；
   **新玩法**默认新建独立文件并登记槽（见 AGENTS.md §1.5）。
5. **增强模块（02/03/05/06/07）只许"包装白名单函数"**，不许直接改写 01 系列内部实现，
   并保持"整段可回退"。
6. **改结构前后跑一次依赖体检**：`python3 tools/dep_report.py`
   （按关键词定位用 `--map <关键词>`）。若「被依赖 Top」或「跨文件调用总次数」大幅上升，
   请在《改动说明》里写明理由。
7. 详细治理契约见 `AGENTS.md` §8 与各文件头「E3 耦合契约」注释；层依赖硬门禁由 `tools/w6_layer.py` 强制。

> 一句话：**耦合可以高（历史现状），但不能"乱上加乱"——新代码只许从白名单入口进。**

> 一句话总结：**你只管 `index.html` 好不好用；技术上的乱与不乱，已经替你收进抽屉里了。**
