# 部署说明

> 适用于「瓶子专注」两种产物。所有路径都是相对路径，放在任意静态托管的根目录 / 子目录都能跑。

---

## 一、两种产物，别搞混

| 产物 | 命令 | 位置 | 用途 | 可还原源码 |
|---|---|---|---|---|
| 单文件 | `python3 tools/build.py` | `index.html`（约 2.9 MB） | 发给别人、本地 file:// 双击打开 | ✅ 首行 `<!--@tomato-src-->` 带完整分片清单 |
| 多产物 | `python3 tools/build.py --multi` | `public/` | 线上部署 | ❌ 不含恢复清单（外链后偏移无意义） |

两者都从 `src/` 构建，**永远不要手改产物**。

---

## 二、多产物目录

```
public/
├── index.html                壳：HTML + CSP + config.js + 9 个 <script src>
├── config.js                 运行期配置（no-cache / network-first）
├── assets/
│   ├── app.9.<hash>.js       纯函数核心，最先执行
│   ├── app.1.<hash>.js       业务主干（32 个源文件合并）
│   ├── app.2..8.<hash>.js    其余槽
│   └── style.<hash>.css      两个 <style> 块合并，id="jyvx-css"
├── sw.js                     PRECACHE 由构建注入，BUILD_ID = index.html sha256 前 12 位
├── manifest.webmanifest
└── icons/
```

- 文件名里的 `<hash>` 是内容哈希，**内容不变文件名不变**，可以放心发长缓存。
- `config.js` 是唯一要短缓存的文件。
- `<script src>` **不带 defer / async**：与内联脚本执行时机等价。

## 三、nginx 片段

```nginx
server {
  root /var/www/bottle/public;
  index index.html;

  # 带 hash 的静态资源：一年，immutable
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
  }

  # 配置：每次都问一下服务端
  location = /config.js {
    add_header Cache-Control "no-cache";
  }

  # Service Worker：不许缓存，否则用户永远拿不到新 SW
  location = /sw.js {
    add_header Cache-Control "no-cache";
  }

  # 入口：协商缓存（配 ETag / Last-Modified）
  location = /index.html {
    add_header Cache-Control "no-cache";
  }

  gzip on;
  gzip_types text/css application/javascript application/manifest+json image/svg+xml;
  gzip_min_length 1024;
}
```

## 四、GitHub Pages

- 直接把 `public/` 里的内容推到 `gh-pages` / `main` 的根目录。
- Pages 会自动带 gzip + ETag，`sw.js` 的 `no-cache` 仍然生效（SW 每次安装/更新都会重新取）。
- 拿不到 `immutable` 头不影响：回访的 0 字节靠 Service Worker 的 CacheStorage，不靠 HTTP 缓存头。

## 五、发版流程

```bash
python3 tools/build.py                 # 单文件（本地分发用）
python3 tools/build.py --multi         # 多产物
python3 tools/build.py --check         # 单文件产物与 src 一致
python3 tools/verify.py --fast         # 21 项门禁
python3 tools/run_smoke.py --html http://127.0.0.1:PORT/   # 多产物全量断言
```

上传 `public/` 后，**必须确认两处 BUILD_ID 一致**：

```bash
sha256sum public/index.html | cut -c1-12      # 例如 895b1aae2a37
grep "const BUILD_ID" public/sw.js            # 必须同上
```

不一致 = 老用户永远拿不到新缓存。

## 六、离线与缓存行为

| 场景 | 行为 |
|---|---|
| 首次访问 | 下载 index + 9 个 JS + CSS + 图标；SW 安装并预缓存 14 项 |
| 回访（版本未变） | SW 命中 CacheStorage，0 字节；`config.js` 走网络协商 |
| 发版 | 新 `sw.js` 安装 → `activate` 只删「≥2 代之前」的缓存，保留上一代一个宽限期 |
| 离线 | 导航回落到 CacheStorage 的 `index.html`；静态资源走 cache-first |
| 离线且从未缓存过 | 返回 503 离线提示页 |

`activate` 保留一代是刻意的：旧页面可能还活着、还引用上一代的 `app.*.js`，立刻全删会让它离线重载失败。

---

## 七、回滚

- **整站回滚**：把上一版 `public/` 目录整体换回即可（`sw.js` 的 BUILD_ID 随之变化，用户下次导航自动接管）。
- **只回滚代码**：`git revert` 对应提交 → 重新 `build --multi` → 上传。
- **不要**只替换 `assets/` 里的文件：文件名带哈希，替换后 index 仍指向旧名，等于没换。

---

## 八、排错

```bash
python3 tools/build.py --multi --debug
# 额外产出 assets/style.debug.css 与 assets/app.debug.js（未压缩，行号对得上 src）
```

- 控制台出现 `violates ... "script-src 'unsafe-inline'"`：说明 CSP 少了 `'self'`，多产物会被整站拦掉。
- 页面白屏但网络 200：先看 `config.js` 是否 404（有 `onerror` 兜底，不该白屏），再看 SW 是否缓存了旧 `index.html`。
- `--html` 指向不存在的路径会直接 `exit(2)`，不再静默回落到项目内 `index.html`（那会产生假绿）。
