# 视觉质感 · 可量的判据

> 敌人不是"不好看"，是"看起来像没做完"。审美没法变成门禁，但可以从**数出来的量**入手：
> 下面每条都有指标 + 阈值 + 机械核对方法。改界面之前先量，改完再量一次。

## 为什么写这份

"做得高级一点""设计感强一点"这类指令之所以无效，是因为它没有指向任何**可改的变量**。
反复让 AI"优化质感"最后总是同一个结果：它去调几个颜色、加一圈阴影、把字调粗一号，
因为那是它唯一能猜到的动作。真正决定观感的量是下面这五个，且都能数出来。

反面证据（本项目 2026-10-25 实测）：
- `font-weight` 字面量 **317 处**，700 用 169 次、800 用 95 次、400 只用 7 次
- `--border` 用 **250 次**，且色彩与正文完全同值
- 20+ 处 `box-shadow: Npx Npx 0 var(--border)` 硬投影
- `body line-height` 是 `normal`

五条加起来就是"简陋"的全部来源，一条都不是"配色不好看"。

## 一、字重：一个界面只该有三种粗细

层级由 **字重 + 字号 + 行高** 共同构成，只靠字号不够。全场同一字重会让界面变成一张加粗海报。

| 角色 | 令牌 | 值 |
|---|---|---|
| 正文 / 描述 / 表格内容 | `--fw-regular` | 400 |
| 标签 / 次要按钮 / 小字强调 | `--fw-medium` | 500 |
| 区块标题 / 主按钮 | `--fw-semibold` | 600 |
| 大号数字 / 页面主标题 | `--fw-bold` | 700 |

**判据：** 任意一屏里 `font-weight >= 700` 的元素数 ≤ 该屏文本节点总数的 **25%**。
超过 → 说明在用粗细代替层级，该降的降。

**核对：**
```js
const h={}; document.querySelectorAll('.view.active *').forEach(e=>{
  if(!e.textContent.trim()||e.children.length)return;
  const w=getComputedStyle(e).fontWeight; h[w]=(h[w]||0)+1;
}); console.log(h);
```

**常见错法：** 13px 的小标签用 700 来"让它显眼"。小字靠字号和颜色已经够显眼，
加粗只会让它和标题抢。小字正确做法是 `--fw-medium` + `--text-light`。

## 二、边框：描边不是装饰，是"可交互"的标记

**判据：**

| 用途 | 宽度 | 颜色 |
|---|---|---|
| 卡片 / 分组的边界 | `1px` | `--border`（半透明，非正文色） |
| 输入框 / 下拉 / 可点胶囊 | `1px` | `--border-strong`（要能看出这是控件） |
| 卡片内部分隔 | `1px` | `--hairline` |
| 强调 / 选中态 | 用**背景色**，不要靠加粗描边 | — |

三条硬规矩：

1. **边框颜色不能等于正文颜色。** 每个输入框、每张卡片都描一道和正文同浓的边，
   页面会像线框图。用 rgba 把同一色相压到 `0.2~0.5` 区间。
2. **同一屏所有边框宽度相同。** 2px/3px 混用会让某几个元素莫名更"重"，
   而这种重量不承载任何信息。全站统一 1px，最多留一个 1.5px 给极小尺寸控件。
3. **虚线只用于"还能往里放东西"的位置**——空状态、拖放区、未填写的槽位。
   用在已有内容之间的分隔线上，等于把成品页面画成草图。

**核对：**
```bash
rg -o 'border(-top|-bottom|-left|-right)?:\s*[0-9.]+px' src/template/*.css \
  | sed 's/.*: *//' | sort | uniq -c | sort -rn
```

## 三、阴影：模拟光，不模拟纸

`Npx Npx 0 var(--border)` 这种无模糊、纯色、右下偏移的硬投影模拟的是**纸张**，
不是光。它让每个元素都像被贴了张纸条。这在 2013 年的扁平化里是风格，现在是"网页玩具"。

**判据：** 全站 `box-shadow` 里 `Npx Npx 0` 形式的硬偏移出现次数 = **0**。

阴影层级按「模糊半径 + 透明度」分档，不按偏移像素分档：

```
--shadow-sm  0 1px 2px  rgba(20,26,48,.07)
--shadow-md  0 2px 6px  rgba(20,26,48,.08), 0 1px 2px rgba(20,26,48,.05)
--shadow     （同 md 档，卡片默认）
--shadow-lg  0 12px 32px rgba(20,26,48,.18)
```

**深色模式必须另给一套**（黑色高透明度）。浅色底上带色相的柔影直接搬到深色底会几乎看不见。

**按下反馈用 `scale(.98)`，不要用位移。** 位移是拟物按键的语汇，触屏上更像布局抖了一下。

## 四、行高：中文要单独定

中文是方块字，同等字号下比西文占更多竖直空间。浏览器默认 `line-height: normal`
对西文够用，对中文偏挤。

**判据：** `body` 的 `line-height` 是具体数值（本项目 `1.5`），不能是 `normal`；
段落级正文 ≥ 1.6；单行标签可用 1.2~1.3。

## 五、主次：一屏只允许一个填充按钮

三个按钮形态相同时（都描边、都填充、都带阴影），只能靠色相区分主次 —— 而色相承载的是**语义**
（绿=开始、红=危险），不是**层级**。层级必须由另一个维度表达。

三档，按"有没有底色"排序：

| 档 | 形态 | 用在哪 |
|---|---|---|
| 实心 | 有填充色 + 无描边 | 一屏唯一的主动作 |
| 描边 | 表面色 + 1px 线 | 次要动作 |
| 幽灵 | 透明 + 无描边，只有文字 | 第三个及以后的、低频动作 |

实心按钮一屏超过一个 = 没有主动作。

## 六、改这些之前

- 设计尺度（字号/圆角/间距/字重/阴影）**只走令牌**，不写字面量（AGENTS.md §2 第 9 条）。
- 一次只改一类（字重 / 边框 / 阴影 / 行高 / 按钮层次），每类单独构建 + 截图核对。
  一次全改完，出问题时无法定位是哪一类导致的。
- 改完跑 `python3 tools/audit_diff.py`，它只审这一轮新增的行，几秒钟出结果。
