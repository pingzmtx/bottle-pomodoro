# 设计令牌（Design Tokens）

> 项目：瓶子专注 · 番茄专注（`index.html` 单文件产物）
> 建立：2026-10-06（W6-8 / W6-9）
> 目的：把"肉眼可见的乱"（字号/圆角/间距）收敛成有限档位，并由 `tools/build.py --lint` **机器守门**。

---

## 0. 为什么要有这套东西

这个项目功能层面已经不缺什么，但**看起来不专业**。原因不是代码行数，是**设计尺度没统一**：

| 属性 | 收敛前 | 收敛后 | 档位数 |
|---|---|---|---|
| 字号 `font-size` | 44 种（含 7 个半像素 9.5/10.5/11.5/12.5/13.5/14.5/15.5px） | **9 档** | ✅ |
| 圆角 `border-radius` | 19 种（2~30px） | **7 档** | ✅ |
| 间距 `padding/margin/gap` | 25 种（1~40px 几乎每个整数都有） | **10 档** | ✅ |
| 颜色 | 132 个变量 / 引用 1607 次，但 **约 800 处硬编码**绕过变量 | 待收 | ⏳ |

**关键认知**：这些值的"变种特别多"不是有人故意设计，是**加功能时随手写**攒出来的。
收敛到档位后视觉**几乎无差**（见下文实测），但代码从此可读、可换肤、可被机器检查。

## 1. 字号 `--fs-*`（9 档）

定义在 `src/template.html` 的 `:root`。**复用项目原有变量名**，194 处 JS 引用零改动。

| 变量 | 值 | 吸收的原值 |
|---|---|---|
| `--fs-micro` | 10px | 9 / 9.5 / 10 / 10.5 |
| `--fs-tiny` | 11px | 11 / 11.5 |
| `--fs-caption` | 12px | 12 / 12.5 |
| `--fs-note` | 13px | 13 / 13.5 |
| `--fs-body` | 15px | 14 / 14.5 / 15 / 15.5 |
| `--fs-title` | 17px | 16 / 17 / 18 |
| `--fs-sub` | 20px | 19 / 20 / 21 |
| `--fs-hero` | 22px | 22 |
| `--fs-h1` | 24px | 24 |

**豁免**：① `@media` 内的响应式字号 ② `>24px`（时钟 120px、大数字 104px 等，各自独用、互不相邻，归并会压缩版面）。

## 2. 圆角 `--radius-*`（7 档）

| 变量 | 值 | 用途 |
|---|---|---|
| `--radius-xs` | 4px | 小徽章、进度条 |
| `--radius-sm` | 6px | 小按钮、次级卡片 |
| `--radius` | 8px | **主力档** |
| `--radius-md` | 12px | 卡片 |
| `--radius-lg` | 16px | 大卡片、面板 |
| `--radius-xl` | 24px | 弹窗 |
| `--radius-full` | 999px | 胶囊、药丸、圆形图标底 |

**注意（语义纠错）**：原 20/26/30px 长在**高度 17~42px 的胶囊/badge** 上——圆角早已超过元素半高，本来就渲染成药丸。
收进 `--radius-full` 是**修正语义写错**，不是尺度缩放。同理 `50%` 的圆形头像**保留 50%**，不换成 999px。

**豁免**：① `@media` 内 ② `50%`（正圆） ③ 角部特写简写里的 `0`。

## 3. 间距 `--sp-*`（10 档）

**档位按「实际用量」定，不是硬套 4px 栅格。** 本项目用量前四名是 8/10/6/4px；
强行对齐 4 栅格会把 203 处 `10px` 压成 `8px`（那是**真实位移**，不是收敛），得不偿失。

| 变量 | 值 | 用量（收编后引用数） |
|---|---|---|
| `--sp-2` | 2px | 218 |
| `--sp-4` | 4px | 289 |
| `--sp-6` | 6px | 338 |
| `--sp-8` | 8px | **456**（主力） |
| `--sp-10` | 10px | 338 |
| `--sp-12` | 12px | 163 |
| `--sp-14` | 14px | 96 |
| `--sp-16` | 16px | 52 |
| `--sp-20` | 20px | 28 |
| `--sp-24` | 24px | 10 |

**豁免**：① `@media` 内 ② `>24px`（页面级留白/版面，如 `40px`） ③ 负值（定位偏移，如 `-2px`） ④ `%` / `auto` / `calc()` / `var()`。
**同时覆盖 CSS 与 JS 内联样式**：JS 里的 `padding:8px;` 字符串 / `cssText` / `style=""` 片段用同一套规则收口。

## 4. 门禁（机器守门，防回流）

三条规则都写在 `tools/build.py` 的 `lint()` 里，**违反即 LINT FAIL**（`verify.py` 全绿链跑不过）：

1. **字号**：`@media` 外、值 ≤24px 的硬编码 `font-size:Npx` → FAIL
2. **圆角**：`@media` 外、非 `var()` 非 `%` 的 `border-radius:Npx` → FAIL
3. **间距**：`@media` 外、值 1~24px 且不在 `--sp-*` 档位上的 `padding/margin/gap` → FAIL

**报错会指出 `文件:行号` 和原值**，直接告诉你改哪个。

> 为什么必须机器守：这三条规则以前只写在文档里（如"字号别乱写"），
> 结果是"规则和机器脱钩"——文档说一套，代码随便写，等于没有规则。
> 与 `w6_layer.py`（层依赖）、`w6_size.py`（单文件行数）同源思路。

## 5. 颜色：**刻意不收**（这是有依据的决定，不是遗漏）

现状：变量 **30 个**，字面量 **649 种 / 1411 处**。

比例悬殊到 649:30，说明多数**不是"漂移"，是"缺词汇"** —— 大量是正经的一次性色（奖章金、段位色、渐变、图表系列），或根本没有对应变量可归。

### 决定性证据：同类色差 ≠ 同种性质

实测两对，色差几乎一样大，性质却完全相反：

| 一对 | 色差 | 真实性质 |
|---|---|---|
| `#eee` (16 处) ~ `--bg` `#f5f0e8` | ΔE 9.4 | **不同色系**（灰底 vs 米白底）——合并会让页面明显变色 |
| `#1a2440` (8 处) ~ `#1b2440` (1 处) | ΔE 8.0 | **同一个颜色的笔误**（差 1/255，肉眼不可辨）——该合并 |

**任何按数值跑的脚本都区分不了这两行**，强转会做出肉眼可见的错误。
（字号/圆角/间距能机械收，是因为它们的前提"同一意图写了不同数"成立；颜色不成立。）

### 所以对颜色的处理是

1. **不做批量改写**。真有价值的只是那 212 处"与已有变量精确同值"的，但那里面 `#ffffff` 对应 4 个变量（`--white`/`--card`/`--surface-1`/`--on-primary`）、`#e85d3a` 同时是 `--primary` 和 `--work` —— **按值选不出该用哪个，硬选等于语义写错**，需要人逐处判断。
2. **规模公开可见**：`lint()` 每次打印一行 W6-10 审计（**不阻断**），明细跑
   `python3 tools/w6_color.py`。
3. 该工具会列出**近似对**（疑似笔误，如 `#1a2440` vs `#1b2440`）供人工裁决，
   但它**只提名、不改动** —— 因为它区分不了上表那两种情况。

> 一句话：字号/圆角/间距是"机器守标准"，颜色只能"机器报数、人来定"。

## 7. 改这些值时怎么做

- **要加新档位**？先问"现有的 9/7/10 档真的不够用吗"。多数情况是套错档，不是缺档。
- **真的需要新档**：改 `:root` 定义 + `tools/build.py` 里的合法档位集合（字号在 `lint()` 字号段、圆角是 `RADIUS` 表、间距是 `_sp_ok` 集合），两处必须同时改，否则门禁会拦你自己。
- **别调门禁阈值来"过检"**：报 FAIL 说明真有问题，按档位改值，不是放宽规则。
- **批量改值**：`/var/minis/workspace/pomo/` 下有 `fs_scale.py` / `radius_scale.py` / `sp_apply.py` 三个脚本（默认 dry-run，加 `--apply` 才写盘），改档位映射后重跑即可。

## 8. 主题配色令牌（R-W8-1）

主题系统的**色彩**令牌（结构令牌 `--sp-*`/`--fs-*`/`--radius-*`/`--shadow-*` **不参与**主题覆盖，见纪律②）。

### 8.1 覆盖机制
```css
:root                     { --primary: #E85D3A; }   /* 默认主题 = 项目原配色 */
body[data-theme="nord"]   { --primary: #5E81AC; }   /* 主题覆盖（浅色） */
body.dark-mode[data-theme="nord"] { --primary: #88C0D0; }  /* 主题覆盖（深色） */
```
CSS 变量在**使用点**解析，`body` 是 `html` 的后代，继承链更近 → `body[data-theme]` 稳定覆盖 `:root`。

### 8.2 每个主题定义的 49 个色彩令牌
| 组 | 令牌 |
|---|---|
| 顶栏 | `--header-hi` `--header-lo` `--header-dark-hi` |
| 底/卡 | `--bg` `--card` `--surface-0..3` `--surface-hover` |
| 文字 | `--text` `--text-light` `--ink-mute` `--ink-strong` `--on-primary` |
| 描边 | `--border` |
| 品牌 | `--primary` `--primary-dark` `--primary-rgb` |
| 语义色 | `--green(-dark)` `--yellow(-dark)` `--red` `--blue(-dark)` |
| 提示底 | `--ok-bg` `--ok-line` `--warn-bg` `--info-bg` `--info-ink` `--info-line` `--accent-bg` `--accent-ink` |
| 图表 | `--c-full` `--c-half` `--c-min` `--c-int` `--c-sleep` `--c-mental` `--c-energy` `--c-pleasure` `--c-grid` `--c-axis` |
| 圆盘 | `--glass-hi` `--glass-mid` `--glass-lo` |

### 8.3 三条纪律

1. **默认主题 = 原值**。`default` 必须与改造前**逐像素一致**，这是所有改动的前提。
2. **只覆盖色彩，不动结构**。`--shadow*` / `--radius*` / `--fs*` / `--sp*` / `--hm*` 一律不参与主题切换 —— 换主题改的是"性格"，不是"体型"。
3. **不碰内联属性选择器**。`template.html` 的 14 个 `[style*="#FDF2E9"]` 依赖 HTML 内联字面量（徽章卡背景），它们与主题无关，刻意不改。

### 8.4 加一套新主题
1. `src/template.html`：加 `body[data-theme="x"] { ...49 令牌... }` + `body.dark-mode[data-theme="x"] { ... }`
2. `src/scripts/0E_theme_主题引擎.js`：`THEMES` 表加一条 `{ name, tag, swatch: [背景色, 主色, 强调色] }`
3. 色值需满足对比度要求，不要自创近似色
4. 跑对比度审计：正文/底 ≥ 4.5，主色上的文字 ≥ 3.0（AA Large）
5. `python3 tools/build.py && python3 tools/verify.py`

> **色卡 swatch 必须用主题自身的色值（写死）**，不能引用 `var(--primary)` 等活令牌 ——
> 否则所有色卡会跟着当前主题一起变色，预览失去意义。
