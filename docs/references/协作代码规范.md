# 📐 协作代码规范（M5 v1）——约束后续任何 AI / 人参与

> 适用范围：`/workspace/src/**`（源文件）。**入口铁律见 §0；违规即算事故级问题。**

## 0. 流程铁律（最高优先级）

1. 改代码一律在 `src/scripts/*.js` / `src/template.html`；**禁止直接编辑 index.html**（会被 build 覆盖）。
2. 每次改动后按序执行：
   ```bash
   python3 tools/build.py --lint   # 结构自检（槽/文件/标记一致）
   python3 tools/build.py          # 合并出 index.html
   python3 tools/verify.py --e2e   # 全绿链 9 段，全绿才算完（run_smoke 单独跑=99 断言）
   node tools/tests/unit_pure.js   # 纯函数单测（动了 00_pure_core 或纯函数必跑）
   ```
3. 大改前先 `cp index.html /root/.codebuddy/artifact/baseline/…`；改完留「整段可回退」注释。
4. 每轮只交付**可验证**结果；先跑一次回归确认基线绿，再动手。

## 1. 目录与命名

- 纯函数（不碰 DOM/appData/存储）→ `00_pure_core.js`，Node 可测；迁函数**原样拷贝 + 原处删定义留 `/* (M4d) xx 已迁移至 00_pure_core.js */`**，禁止双份。
- 主引擎按 `01a_prelude / 01b_data / 01c_timer / 01d_features / 01e_ui / 01f_immersive / 01g_init` 分段；同职责函数收敛到对应段。
- 新 UI 组件 → 用 `registerComponent()`（08），不要手写"极简黑名单/折叠/样式"多处登记。
- 文件命名：两位序号 + 职责词；模块内函数带统一前缀（如 `__uiFold`、`__comp`、`__errRep`）。

## 2. 声明与作用域

- **全局函数是稀缺资源**：新增全局名先 `grep` 是否已存在（雷区 1）；能收进已有命名空间就不新增全局。
- 私有 helper 各模块自持时**别共用裸名**（`_el/_save/_pad…` 历史重复源）：新代码用「模块前缀 + 词」（`__uiFold._apply` 风格）。
- 不用裸 `this` 传参；IIFE 内部变量不外泄。
- 包装式注入只用于"增强现有函数"，被包函数与包装函数写在相邻处并注明。

## 3. 语法与风格（老浏览器友好，雷区 10）

- 默认 **ES5/低 ES6**：`var` 为主；新函数体内部可用 `const/let`（**一函数内不混用 var 与 const/let 声明同一批变量**——历史风格债，新代码起逐步收敛）。
- 字符串统一单引号；模板字符串仅用于明显拼接收益处。
- 缩进 2 空格；`if/for` 后不加分号单行展开的"极长行"**新代码禁止**（历史 minified 行为遗留债，改到那行才顺手拆）。
- 换行：一行 ≤120 字符（中文文案按语义断）。

## 4. 注释纪律

- 每个模块/组件文件头：`职责 / 为什么存在 / 何时可删 / 整段可回退标记`。
- 关键修复写「现象 → 根因 → 方案」，方便后续 AI 不再踩。
- **改注释里的行号/断言数要同步**（历史：多处手写 74/88 断言号过期）。
- 加功能若改动产品文案，先经用户确认，不在正文里夹带测试性文案。

## 5. 安全与数据

- 用户可控文本渲染前过 `escapeHtml`（或 DOM `textContent`）；新写 `innerHTML` 拼用户字段 = 红线。
- 成就/段位/赛季永不清；删数据走 导出/归档；`localStorage` 新键走 `tomato_*_v1` 命名并登记进交接手册 3.4。

## 6. 测试

- 新纯函数 → `00_pure_core.js` + `tools/tests/unit_pure.js` 用例。
- 新交互/组件 → 回归集加用例（`@case("C2x …")`，自造状态、不依赖前面用例）。
- 回归暴露产品 bug：先修产品；只有用例写错才改用例。
