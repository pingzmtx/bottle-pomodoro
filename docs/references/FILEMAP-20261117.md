# 文件名对照表（阶段 6，2026-11-17）

2026-11-17 之前，71 个源文件的名字带着加载序号前缀（`01e5_ui_tree.js`）。阶段 3 把「加载顺序」
交给 `src/manifest.json` 之后，序号就没用了，阶段 6 一次性摘掉。**语义键（去前缀后的名字）除一个特例（见文末）外从头到尾没变**，
所以基线、分组表、owner 几乎全都不用动 —— 变的只有文件名本身。

为什么不保留序号：它让人误以为「文件名决定加载顺序」，而这个假设一旦被写进新代码，拆模块就会再踩一次 TDZ。
现在顺序只有 manifest 一个地方说了算。

旧文档/旧提交说明里出现的短号（`01a` / `01d` / `01e` …）就是这张表左边的前缀，按表查即可。

## 特例

`01e2b_ui_immersive_poster.js` 的前缀是 `01e2b_`（4 位字母数字），超出了去前缀规则
`^[0-9][0-9A-Za-z]{0,3}_`，所以它的语义键当时就是它自己的文件名。阶段 6 一并改成
`ui_immersive_poster.js`，键随之从 `01e2b_ui_immersive_poster` 变成 `ui_immersive_poster`
（这是全批唯一一个键真变了的文件）。
