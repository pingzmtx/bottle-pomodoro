## 五、执行方案（三选一，推荐 T2）

### T1 —— 只切 A（最小、最安全）

- 新增 `01d5_engine_stats.js`（A 段）。
- `01d` → 3977 − 1383 = **2594 行**。
- 优点：A 段自足性最高（13 个符号段内自引用），单一区间。
- 缺点：B 段（`monthStats`/`yearStats`）与 A 同属统计域却留在 `01d`；C 段工具函数仍散在文件尾。

### T2 —— 切 A + B（**推荐**）

- 新增 `01d5_engine_stats.js`（A 段 + B 段**合并**，两区间拼入同一文件）。
- `01d` → 3977 − 1383 − 32 = **2562 行**。
- 优点：**统计域完整归位**——`monthStats`/`yearStats` 本就是「统计」语义，与 A 同文件消除「半拆」状态；B 段仅 976 B，边际成本极低。
- 代价：B 段不连续（中间隔着 UI 态/疲劳/幽灵，L2038–2156），需**两区间拼接**——但这两区间各自干净，拼接后文件语法已由 acorn 校验。
- 注：`fmtDurMin` 是通用格式化工具，随 B 走（它只被 `01e7` 与 A 段用），放统计文件内合理。

### T3 —— 切 A + B + C（最彻底）

- 新增 `01d5_engine_stats.js`（A+B）+ `01d6_engine_util.js`（C 段 7 工具）。
- `01d` → **2509 行**。
- 优点：`01d` 只剩「成就 + 段位 + 树养成」主干，最接近终局。
- **风险**：C 段被 `01d3`/`01d4` 调用（7 处 + 2 处）。虽同为 slot 1、定义顺序在前即可解析，但**把工具函数从主干再挪走，等于让两个已拆文件多一层间接依赖**；C 段仅 55 行，收益（55 行）与「新增一个文件 + 2 条跨文件边」的复杂度不成正比。
- **建议**：**本批不做 C**。留在 §八「工具函数归位」独立议题里，等主干形态稳定后再评估。
